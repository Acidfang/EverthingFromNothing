# Source input and addressed operations

The page opens the source workspace. Input is retained exactly, with its address,
previous context links and capture receipt. It is not converted into an authored
assistant answer. The active input path no longer dispatches fixed English
questions, slash-command reply templates, phrase tables, exact-label questions or
an inference provider. Those routes did not implement the requested meaning and
intent mechanism.

Earlier conversation records remain readable. Historical paired turns retain
their original source and common receipt. New `capture-only` inputs retain one
user record and a capture receipt; no missing assistant message is fabricated.
Turn numbering follows retained turn identities. Original text and subsequent
explicit corrections remain separate.

## What can execute

The source workspace reads actual addressed records and relationships. Selecting
a record reveals its retained WAS, current IS, source and receipts. An explicit
proposed edit or child record supplies its own candidate and exact-value
conditions. The engine filters those conditions, keeps alternatives, requires
selection for a user-owned continuation, stages the selected records, and checks
the actual displayed values before admission. Optional browser persistence uses
a compare-and-store operation and readback before the UI adopts the result.

The underlying relation evaluator can read a supplied address, follow an explicit
sequence of relations, compare or filter supplied values, and reconstruct source
and receipt paths. These are typed record operations. They are not a reduction
from arbitrary language to intent, and the conversation input does not guess that
reduction through word matching.

## Source correspondence and remaining work

- `INPUT = RETURN_FROM_SOURCE_NODE`: preserve input, source, address and receipt;
  input does not automatically establish intent, command, truth or NEXT
- `READ_SOURCE → FIND_ADDRESS → SEE_DIFFERENCE → FILTER_TO_ALLOWED_CONTINUATIONS`:
  supplied records, explicit exact-value conditions and candidate patches
- `IF_ONE_CONTINUE / IF_NONE_REST_OR_UNRESOLVED / IF_MINE_STOP_FOR_USER_SELECTION`:
  the candidate engine preserves those distinct cases
- `RECORD_SELECTION → CONTINUE`: actual staged values, returned readback, receipt
  and retained history share one execution identity
- Whole context plus focused Difference, receipts and current relations: retained
  context is assembled without discarding earlier inputs
- `Δ@z⇒Fz=z⋈Δ⋈Fz≅N⊂N`: at the declared text-comparison grain, an actual unequal
  before/after pair at one address produces a fracture record and return links

The source definitions name interpretation/intent and reply composition, but the
current implementation has no source-derived executable reduction for them.
Capture-only is therefore partial. No replacement prose, phrase table, physical
law or conventional gate truth table is inserted to fill that gap.

## One transition and its fracture records

The same issued execution determines selected candidate identity, affected gate
ports, retained parent graph, explicit threads and staged output. The page checks
its bound DOM records and displayed address values before admitting the result.
A mismatched, incomplete, stale or cancelled return cannot become current state.

The fracture producer consumes actual retained histories and the selected staged
state. Unequal text at the same address produces a witnessed text Difference.
New records are baselines; they are not compared against invented values. Source,
revision and receipt references remain attached. PROPOSED changes stay distinct
from RETAINED changes. Multiple parent links remain separate. Exact graph
reachability is preserved; bounded path enumeration reports incomplete evidence
rather than dropping graph edges or inventing a completed root return.

The act's producer is the local source address and may be a child grain. Unrelated
or upstream records do not gain fabricated paths to that source. The same
producer is available at another supplied grain; it does not automatically
populate new children or continuations.

The tetra drawing presents gate records. Indexed infinity moments, the directed
port, relation-defined spatial placement and full inherited motion remain
unbound. The old six-face preview is not mounted as the page's model. This change
does not deliver the requested complete animated fracture field.

## Receipts, recovery and storage

Committed receipts reconstruct their original proposed records after later edits
or session recovery. This replays retained data; it does not re-observe a past
screen. Existing receipt schemas retain their original address-value checks.
Generic diagnostic notes are omitted from the conversation presentation; actual
check status, mismatches, sources and stored receipt data remain inspectable.

Session v2 normalizes repeated objects, arrays and canonical JSON strings with
checked references. Recovery reproduces exact text, then runs full ledger replay.
Version 1 remains readable. Malformed references, duplicate keys, cycles, changed
history, stale writes and byte/depth/node limits reject without partial admission.
Stored sessions are limited to 1 MiB and expanded ledgers to 4 MiB; those are
implementation resource bounds. Browser storage is opt-in and unencrypted.
Entered content stays in the browser unless the user explicitly exports it.

## One identity across mechanism grains

State, node, pixel, address and coordinate handles share the same canonical
entity. WAS/IS/NEXT keep distinct state revisions and source references on that
entity. Gate ordinals and fracture tuples are view/derivation keys, not new field
entities. Grain changes alone do not mutate the ledger, create children or advance
an Act. Numeric projection remains unbound unless an actual mapping supplies it.

The visible field filter resolves all selected grain handles to canonical field
addresses and invokes the existing explicit exact-value evaluator. Equal address
sets give the same query, matches, unknowns and proof in every grain. Historical,
proposed, fabricated or stale handles cannot select a current operation target.
The operator and predicate are explicit; an unknown predicate remains unbound.
